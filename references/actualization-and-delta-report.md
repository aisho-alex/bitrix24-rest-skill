# Актуализация выгрузки и отчёт о дельте

Когда: в каталоге уже лежит история по задаче, звучит «актуализируй» / «обнови из <ссылка>».
Ожидаемый результат — обновлённые файлы **плюс** разбор того, что появилось нового.
Просто перезапустить скрипт и ответить «готово» — это половина задачи.

## 1. Точка отсчёта (до запуска)

```bash
cd <dir>
for f in *.md; do echo "== $f"; head -8 "$f"; wc -l "$f"; done
ls -la
```

Из шапок выписать по каждому чату:
- `Сообщений: N` (и `содержательных: M`);
- конец `Период: <start> — <last_TS>` — это и есть маркер «что нового»;
- из `task_<id>.md`: строку `изменена:`, стадию/статус, дедлайн, состав соисполнителей/наблюдателей.

Надёжнее — сохранить копию: `cp -r <dir> /tmp/<name>_prev` и потом `diff` по нужным файлам.

## 2. Перезапуск

```bash
python3 scripts/fetch_bitrix_task_context.py <task_id> --out-dir . --limit 1000
```

Смотреть на вывод: «Чат chatNNN: K сообщений» — сравнить с прошлым K.
Проверка на обрезку: если K совпал с `--limit` — история обрезана, поднять лимит.

## 3. Извлечение нового

```bash
# по каждому чату, где прибавилось
awk '/^### \[<предыдущий_последний_TS>/{f=1} f' task_<id>_chat<NNN>.md | sed 's/^-\{10,\}$//'
# сколько всего заголовков попало
awk '/^### \[<TS>/{f=1} f' task_<id>_chat<NNN>.md | grep -c '^### \['
```

Сообщения-цитаты (`---` + «Автор [сегодня, HH:MM] #...» + текст + `---`) — это ответы, а не дубликаты;
в дайджест идёт ответ, а исходный вопрос берётся из цитаты. Когда цитаты раздувают вывод
(в переписке 20+ сообщений это треть объёма), их можно срезать целиком — переключателем по
строкам из дефисов:

```bash
awk 'BEGIN{s=0} /^-{50,}$/{s=1-s; next} s==0{print}' task_<id>_chat<NNN>.md
```

Проверено на дампе 225 сообщений: ответы остаются читаемыми, объём падает примерно на треть.

Если вывод длинный — резать `head -300` и добирать хвост отдельным `awk` от TS последнего
показанного сообщения. Проверять, что дошли до самого конца периода из шапки.

Проверка состава контекста (не появилось ли новых чатов в новых сообщениях):

```bash
grep -ohE 'IM_DIALOG=[A-Za-z0-9]+' *.md | sort | uniq -c
grep -oE 'chat[0-9]{5,7}' *.md | sort | uniq -c
```

В ссылках вида `#123:111111/25167127` второй номер — id сообщения, а не чат: новые диалоги
искать только по `IM_DIALOG=chatNNN`. Нашлись — дотянуть точечно `--dialog chat<NNN>`.

## 4. Шаблон отчёта

Простой текст под терминал, без markdown-разметки. Порядок блоков:

1. Файлы: абсолютные пути, что перезаписано и во сколько, было → стало по сообщениям по каждому чату.
   Чаты без изменений — одной строкой с датой последнего сообщения («тишина с 16.09 12:17»).
   Отдельно — что поменялось в карточке (изменена, наблюдатели, стадия). Стадия и дедлайн ходят
   между выгрузками (16.09 было 4516, 21.09 — 4518), а дедлайн может истекать в день актуализации:
   проверить и сказать вслух. Системные сообщения в чате («добавил наблюдателя», «изменил стадию»,
   «задача почти просрочена») несут те же факты и приходят раньше, чем правка шапки.
2. «Новое в чате задачи (N сообщений, <диапазон времени по порталу>)».
3. Темы — нумерованным списком, **сгруппированно по смыслу, а не по хронологии**: решённые
   вопросы, новые блокеры, инциденты, доступы/роли, организационное (созвоны, МР, токены).
4. «Обещанные сроки» — кто, что и когда обязался сделать (из-за этого пункта дайджест и нужен).
5. Пометка сообщений самого пользователя вебхука и того, что ответили на его вопрос:
   за этим к выгрузке и возвращаются.
6. Одна строка-вопрос про `untracked` каталог в git, если каталог не отслеживается.

Стиль: короткая мысль на строку, конкретные числа и имена файлов/модулей сохранять как в источнике,
без воды и без «успешно выполнено».

## Наблюдения по живой задаче (типовой случай)

- Чат задачи (`chatId` из карточки) — самый живой; чаты из описания («Основной чат обсуждения»,
  «техвстреча») могут молчать сутками, их выгрузка при этом не меняется.
- Реплики, которые дают «числа» (замеры, отказы, приговоры по доступам), стоит помечать —
  по ним потом восстанавливают хронологию решений. Точки роста контекста: новые МР, заявки,
  токены/роли, термины, введённые в оборот в этой переписке.
- В карточке обычно нет комментариев форума — обсуждение целиком в чатах,
  `task.commentitem.getlist` не нужен.

## Черновик сообщения в рабочий чат (частая вторая половина задачи)

Часто после разбора нужен не отчёт, а сообщение: «сохрани описание, я кину в чат битрикса».
Первоисточник тут — журнал проекта и свои наблюдения, а не переписка.

Принятая форма (сплошной человекочитаемый текст, абзацами, без таблиц и разметки):

1. Вступление: что делал, на чём и чем ограничивался («только предварительный расчёт, полисы
   и оплату не создавал»).
2. Разделы по направлениям работы — словами-заголовками внутри строки (АДРЕСА. ЖИВОЙ РАСЧЁТ.
   ЗАМЕРЫ.), внутри числа вписаны в предложения.
3. Что предлагается решить адресатам, а не тебе — прямым текстом.
4. Риск, который считаешь важнее прочего — отдельным абзацем.
5. ЧТО В ГИТЕ: ветка, что в ней, есть ли МР.
6. ЧТО ОСТАЛОСЬ: пункт за пунктом, с адресатом («вопрос владельцу стенда»), включая оговорку
   про одноразовость замеров и свои же дефекты методики.
7. Ссылки на первоисточник (журнал) и на отчёт с цифрами.

Правила: от первого лица («прогнал», «проверил») — сообщение уходит от имени пользователя; числа
только из источников; файл называть абсолютным путём у текст показывать целиком, чтобы
копировался из терминала. Структурированный вариант (заголовки, `===`, списки) держать только
как добавку рядом — если о нём спросят отдельно.

Где хранить черновик: рядом с журналом в каталоге, который не попадёт в git (`var/`,
`.gitignore`), либо в личной папке. Не в трекаемой части чужого репозитория.
